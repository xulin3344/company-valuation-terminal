# PRD：万能估值器应用（Universal Valuation Engine）

> 上游依据：`docs/万能估值器应用方案.md`（总体方案）、`估值范例表/`（泡泡玛特五模型估值范式）
> 开发模式：Loop 循环开发（实现 → 自测 → 验收门禁 → 修复直至全绿 → 下一 Loop）

---

## 1. Requirement Background（需求背景）

项目源于一套以泡泡玛特（09992.HK）为标的、用 Google Sheets 手工构建的投行级估值范例表（`估值范例表/` 目录：DCF_Model、Trading_Comps、SOTP_Valuation、Valuation_Summary 四张表，五大模型各 20% 权重跨表勾稽）。该范式专业完整，但高度依赖手工：更换标的需要重建全部公式与勾稽，无法快速横向对比，且要求使用者具备投行建模技能。

本 PRD 将总体方案转化为可执行、可循环验收的产品需求：构建"万能估值器"Web 应用——输入任意港股/美股上市公司代码，自动抓取财报、生成初始估值假设、运行五大估值模型（DCF-Gordon、DCF-Exit、Comps-P/E、Comps-EV/EBITDA、SOTP）并输出加权汇总看板，全程参数可修正、实时重算。

## 2. Goals and Value（目标与价值）

**目标：**
- G1：输入任意港股/美股代码，30 秒内完成"抓取 → 标准化 → 估值 → 看板"全流程
- G2：估值引擎以范例表数据做回归测试，五大模型目标价还原范例展示值（综合中枢 ¥278.65 等），误差 ≤0.1%（Comps 个别路径因范例源数据舍入放宽至 ≤0.15%，见 §9）
- G3：全部假设参数可修正，修改后全链路重算 <200ms
- G4：数据缺失或公司亏损时引擎自降级（剔除对应模型并重分配权重），而非计算失败

**价值：** 将投行级五模型估值能力产品化，零建模技能即可获得专业估值结果；每个假设透明可见可改，兼具互动式估值学习价值。

## 3. Glossary / Role Definitions（术语定义）

- **DCF**：现金流折现法；**WACC**：加权平均资本成本；**CAPM**：资本资产定价模型（Ke=Rf+β×ERP+规模溢价）
- **UFCF**：无杠杆自由现金流 = EBIT×(1−t) + D&A − CapEx − ΔNWC
- **EV 过桥**：股权价值 = 企业价值 EV + 现金及理财 − 有息负债 − 少数股东权益
- **Trading Comps**：可比公司法；**SOTP**：分部加总估值法
- **Football Field（足球场图）**：各模型估值区间横向对比图
- **三情境**：Bear（悲观）/ Base（基准）/ Bull（乐观）三套倍数/假设参数组
- **Loop（开发循环）**：本项目最小交付单元，流程 = 实现自测（pytest + 范例基准对齐）→ 验收门禁全勾 → 失败项返工直至全绿 → 进入下一 Loop
- **自降级**：引擎根据数据健康度自动剔除不可用模型并按比例重分配其权重

## 4. Applicable Scope（适用范围）

- 适用：港股、美股上市公司估值；覆盖 M1~M5 五个里程碑，M1（估值引擎）为本 PRD 首个开发 Loop 集
- 平台：本地 Web 应用（FastAPI 后端 + Vue3 前端），单机单用户
- 不适用：A股（后续版本）、非上市公司、债券/基金/衍生品估值

## 5. Non-Goals / Out of Scope（非目标）

- 不提供投资建议；界面固定免责声明"输出为模型推演，非投资建议"
- 不做用户系统、多租户、云部署（首版本地运行）
- 不做 PDF/图片报告导出（M5 后可选扩展）
- 不含 tick 级行情、盘口、资金流数据

## 6. Functional Requirements（功能需求）

**M1 估值引擎（FR-E，首个交付集，纯函数、零 IO、可序列化）**
- FR-E1 WACC 模块：CAPM（Ke = Rf + β×ERP + 规模溢价）、税后债务成本 Kd×(1−t)、权债加权输出 WACC
- FR-E2 五年预测生成器：营收增速逐年衰减（可手工覆盖逐格值）、毛利率向历史均值回归、费用率延续；支持完全手工假设
- FR-E3 UFCF 推导：ΔNWC = 营收增量 × ΔNWC占营收增量比（默认 3%）；UFCF = NOPAT + D&A − CapEx − ΔNWC
- FR-E4 DCF-Gordon：TV = UFCF₆/(WACC−g)，折现（中间年份不打折）、EV 过桥、每股目标价
- FR-E5 DCF-Exit：TV = EBITDA₅ × 退出乘数，其余同 FR-E4
- FR-E6 DCF 敏感性：WACC × g 双变量每股矩阵（Gordon 口径）
- FR-E7 Comps 统计：可比池逐家精确倍数（EV/EBITDA、EV/EBIT、P/E、EV/Sales）→ 六档统计（Max/75th/Mean/Median/25th/Min），百分位采用线性插值（Excel PERCENTILE.INC 同口径）
- FR-E8 Comps 估值桥：P/E（直接得股权价值）与 EV/EBITDA、EV/EBIT、EV/Sales（过桥）四路目标价 + 25th/75th 分位区间
- FR-E9 SOTP：动态分部（0~N 个：名称+EBIT+三情境倍数）、三情境 EV/过桥/每股、EV 贡献占比、核心IP×体验分部双变量敏感性
- FR-E10 汇总加权：权重可配置自动归一化；输出加权中枢、加权区间（各模型下限加权~上限加权）、包络区间（全模型极端值）、上行空间、评级分档
- FR-E11 自降级：净利润≤0 剔除 P/E；EBITDA≤0 剔除 EV/EBITDA；零分部剔除 SOTP；剩余权重自动归一化；全部模型不可用时抛出 NoValuationError
- FR-E12 引擎保护：g ≥ WACC 时抛出 InvalidAssumptionError（永续公式发散）

**M2 数据层（FR-D）**：akshare（港股）/ yfinance（美股）Provider 抽象与多源切换；科目标准化映射（YAML 配置，港/美两套）；货币单位归一；数据质量检查报告（缺失科目标注）
**M3 API 层（FR-A）**：`POST /api/analyze`、`POST /api/recalculate`、`GET /api/comps/pool`、项目保存/载入（SQLite）
**M4 前端（FR-U）**：六页工作台（数据总览/假设参数/DCF/可比公司/SOTP/汇总看板）；ECharts 足球场图、敏感性热力图、乘数箱线图；假设面板即时重算；长表容器可滚动可调高；高对比度配色（白底黑字/深底白字）
**M5 联调验收（FR-P）**：端到端演示、项目持久化一致性、免责声明

## 7. Key Flows / Loop 开发循环与验收流程

**Loop 循环定义（每 Loop 五步）：**
1. 明确本 Loop 验收数字（基准值+容差）与边界用例
2. 实现功能代码
3. 自测：pytest 全绿 + 范例基准数字对齐
4. 验收门禁：对照 §9 验收清单逐项勾验
5. 不通过项返工修复，全绿后进入下一 Loop

**M1 拆分为 6 个 Loop（每 Loop 独立门禁）：**

| Loop | 模块 | 验收数字（范例基准） | 容差 |
|---|---|---|---|
| Loop-1 | WACC | CAPM 输入下 Ke=9.94%、Kd税后=2.695%、WACC=9.7951% | ±0.01pp |
| Loop-2 | 预测+UFCF | FY2030E 营收 82,605.87；UFCF 序列至 28,267.55；EBITDA₅=39,816.03 | ±0.1% |
| Loop-3 | DCF 双终值+敏感性 | 预测期现值合计 83,654.69；Gordon ¥273.42 / Exit ¥370.75；EV 352,198.22 / 482,921.45；敏感性矩阵四角 295.46 / 252.90 | ±0.1% |
| Loop-4 | Comps | P/E ¥232.04、EV/EBITDA ¥189.49、EV/EBIT ¥224.34、EV/Sales ¥75.47、EV/EBITDA 区间 176.26~202.89、P/E 区间 218.46~248.01、四路综合 ¥180.33 | ±0.1%（EV/EBITDA 路径 ±0.15%） |
| Loop-5 | SOTP | EV 424,886 / 305,388 / 553,386；每股 327.54 / 238.56 / 423.22；敏感性矩阵角值 236.21 / 417.17 | ±0.1% |
| Loop-6 | 汇总+降级+自动假设 | 加权中枢 ¥278.65、加权区间 236.16~322.98、包络 176.26~426.37、上行空间 94.86%、评级"显著低估"；降级与生成器规则单测 | ±0.1% |

**用户视角端到端流程（M5 后）**：输入代码 → 看板生成 → 修改任意假设 → 实时重算 → 三情境切换 → 保存项目。

## 8. Risks and Dependencies（风险与依赖）

**风险：**
- 范例表部分展示值存在手工舍入（如 P/E 中位显示 24.5，精确反推为 24.4792），回归基准以"标准公式 + 范例输入"计算并对照展示值，容差按 §9 执行
- M2 数据源接口不稳定（akshare 美股覆盖率波动）→ Provider 抽象层多源自动切换
- 自动生成的初始假设可能失真 → 全参数暴露 + 行业默认值 + 历史回归三重参考，用户终审

**依赖：** Python 3.11、pytest（M1）；FastAPI（M3）；akshare / yfinance（M2）；Vue3 + Vite + ECharts（M4）；范例基准数据 `backend/tests/fixtures/basemart.json`（由范例表 HTML 提取并已逐项勾稽验证）

## 9. Acceptance Criteria（验收标准）

**M1 总门禁（全部满足才宣告 M1 完成）：**
- [ ] `pytest backend/tests -v` 全绿，覆盖 Loop-1~6 全部验收数字
- [ ] Loop-1~6 各验收数字对齐（容差 ±0.1%；Comps EV/EBITDA 路径 ±0.15%，原因是范例源数据 13.1x 为 13.0629x 的舍入展示，引擎采用逐家精确倍数取中位的标准口径）
- [ ] 边界用例通过：g ≥ WACC 抛 InvalidAssumptionError；净利≤0/EBITDA≤0/零分部自降级且降级后权重和=1；全部模型不可用抛 NoValuationError
- [ ] 引擎零 IO：engine 目录无网络/文件系统依赖 import
- [ ] 每 Loop 结束输出验收报告（用例数、对齐数字、最大偏差）

**M2~M5 门禁（后续 Loop 展开，先立框架）：**
- [ ] M2：抓取 09992.HK 与 AAPL 输出完整标准科目 + 质量报告；港/美科目映射单测（含 IFRS-16 租赁负债口径差异）通过
- [ ] M3：`/api/recalculate` 传入范例数据返回 ±0.1% 还原；`/api/analyze` 端到端 ≤30s
- [ ] M4：修改 WACC 后全站 <200ms 重算；足球场图/热力图渲染正确；全界面高对比度；长表容器可滚动可调高
- [ ] M5：00700.HK 与 AAPL 端到端演示通过；项目保存/载入数据一致；免责声明展示

## 10. Open Questions（待决问题）

- Q1 评级分档阈值：默认设计为上行空间 <−10% 高估 / −10%~15% 合理 / 15%~50% 低估 / >50% 显著低估，M4 前与用户确认
- Q2 SOTP 分部数量上限：建议 ≤10，Loop-5 实现时确认
- Q3 自动假设生成的增速上限 cap（当前 30%）与永续增长下限（2%）：M2 接入真实财报数据后校准
