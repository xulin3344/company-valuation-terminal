# 万能估值器应用 — 总体方案设计

> 依据：`估值范例表/`（泡泡玛特 09992.HK 五模型加权估值体系）
> 确认决策：①数据输入=自动抓取+手动兜底 ②形态=Python全栈(FastAPI+互动前端) ③市场=港股+美股双模式自适应 ④SOTP=动态分部编辑器

---

## 一、产品定位

**一句话**：输入任意港股/美股上市公司代码 → 自动抓取财报 → 自动生成初始估值假设 → 五大模型估值 → 可视化汇总看板，全程参数可修正、实时重算。

**核心体验流程（对标范例表的勾稽理念）**：

```
输入代码 → [数据层] 抓取财报+行情 → 科目标准化 → 数据质量检查(缺失标注/手动补录)
        → [引擎层] 自动生成初始假设(可改) → DCF×2 / Comps×2 / SOTP 五路并行
        → [汇总层] 权重加权 → 足球场图 + 综合中枢 + 投资评级
        → 用户任意改参数 → 全链路实时重算（不重新抓数据）
```

---

## 二、三大核心设计原理（为什么这样设计）

### 原理 1：科目标准化层 —— 「万能」的根基

**问题**：港股(IFRS)与美股(US GAAP)财报科目名、口径、结构完全不同（营业额 vs Revenue；经营溢利 vs Operating Income；IFRS-16 租赁负债全额计入有息负债而美股口径不同）。

**解法**：引擎**永远只消费内部标准科目**（约 25 个，如 `revenue/ebit/ebitda/net_income/cash/debt/da/capex/shares_diluted`），市场差异全部隔离在**映射配置**中：

```yaml
# config/mapper_hk.yaml
revenue: ["营业额", "收益", "Revenue"]
ebit: ["经营溢利", "营业利润"]
debt: ["借款", "租赁负债", "应付票据"]   # IFRS-16: 租赁负债计入有息负债
# config/mapper_us.yaml
revenue: ["Total Revenue", "Revenue"]
ebit: ["Operating Income"]
debt: ["Long Term Debt", "Current Debt"] # 租赁负债单独口径开关
```

**原理收益**：估值公式与市场解耦 → 新增市场（如A股）只需加一份映射配置，引擎零改动。这就是"两套模式自动适应"的实现方式——**不是两套公式，而是两套映射+两套默认宏观参数**。

### 原理 2：估值引擎参数化 —— 假设即数据

范例表的所有魔法数字（β=1.20、ERP=6.2%、g=3.0%、退出倍数16x、权重20%）在万能器中全部变为 **`Assumptions` 数据对象**：

- 抓取财报后，引擎基于历史数据**自动生成初始假设**（如：Y1~Y5 增速 = 近3年CAGR 线性衰减；β 自动抓取；Rf 按市场取对应国债收益率）
- 用户在前端**逐格修改任意假设** → 触发 `recalculate` → 实时重算
- 三情境（Bear/Base/Bull）= 三套预设假设参数组，一键切换

### 原理 3：可比池自动化 + 引擎自降级

**可比公司从哪来**：按标的所属行业（自动识别）从预置行业分类拉取同行业上市公司清单 → 批量抓取市值/EV/收入/EBITDA/EBIT/净利润 → 计算乘数 → 取中位数/分位数（与范例表 Max/75th/Mean/Median/25th/Min 六档一致）。用户可增删可比公司修正池。

**自降级规则**（保证"任何公司都能算"）：
| 情况 | 处理 |
|---|---|
| 净利润为负 | 自动剔除 P/E 模型，其 20% 权重按比例重分配至其余模型 |
| EBITDA 为负 | 剔除 EV/EBITDA 口径 |
| 无分部数据（SOTP 0 分部） | 自动隐藏 SOTP 模型（已确认决策） |
| 上市历史<2年 | 增速假设回退行业默认值 |
| 必需科目缺失 | 黄色警告 + 手动补录入口，补录前该模型不参与加权 |

## 四、估值引擎规格（公式严格对标范例表）

### 4.1 WACC（CAPM）
```
Ke = Rf + β × ERP + 规模溢价
Kd_after = Kd × (1 − t)
WACC = Ke × We + Kd_after × Wd        （范例: 9.94%×98% + 2.70%×2% ≈ 9.80%）
```
默认参数：港股 Rf=10Y美债、ERP 6.2%；美股 Rf=10Y美债、ERP 5.0%；β 自动抓取。

### 4.2 五年预测（双驱动，默认自动生成）
```
营收: YoY 增速逐年后退（默认近3年CAGR线性衰减至 8%）
毛利: 毛利率逐年向历史均值回归（步长可配）
费用: 费用率延续历史趋势
EBIT = 毛利 − 销售费用 − 管理及研发费用
```

### 4.3 UFCF 与折现
```
UFCF = EBIT × (1−t) + D&A − CapEx − ΔNWC
ΔNWC 默认 = ΔNWC/营收 历史均值 × 当年营收
折现系数 = 1 / (1+WACC)^t
```

### 4.4 双终值口径（与范例完全一致）
| 模型 | 终值 | 范例结果 |
|---|---|---|
| DCF-Gordon | TV = UFCF₆ / (WACC−g) | ¥273.42 |
| DCF-Exit | TV = EBITDA₅ × 退出倍数 | ¥370.75 |

### 4.5 EV → 股权价值过桥（通用化增强）
```
股权价值 = EV + 现金及理财 − 有息负债 − 少数股东权益 − (通用化补充科目)
每股 = 股权价值 / 稀释股本
```
> 范例表为净现金公司（-15,000）未体现少数股东权益；万能器必须加入该科目，否则对有少数股东权益的公司会高估。

### 4.6 可比公司估值桥
```
P/E 法:   股权价值 = 行业中位P/E × 净利润          → 直接得股权价值
EV/EBITDA 法: EV = 中位倍数 × EBITDA → 过桥        → ¥189.49
EV/EBIT 法:   EV = 中位倍数 × EBIT   → 过桥        → ¥224.34
区间: 25th/75th 分位数对标（与范例一致）
```

### 4.7 SOTP（动态分部）
```
分部EV = Σ 分部EBIT_i × 差异化EV/EBIT倍数_i
三情境 = 悲观/基准/乐观三套倍数列（用户逐分部维护）
敏感性: 核心分部倍数 × 其余分部倍数 双变量矩阵
```

### 4.8 汇总加权
```
综合中枢 = Σ 模型目标价_i × 权重_i   （默认各20%，可调，自动归一化）
区间 = 各模型 [下限最小值, 上限最大值]
评级 = 按加权中枢/现价溢价分档（高估/合理/低估/显著低估）
```

## 五、数据模型（核心对象）

```python
# 标准化财报（引擎唯一输入的财务对象）
Financials: {market, currency, fy_list, accounts: {standard_name: [FY2022..FY2025]},
             shares_diluted, price, quality_report}

# 假设集（全部可序列化、可保存）
Assumptions: {wacc:{rf,beta,erp,size_premium,kd,t,we},
              forecast:{revenue_growth[5], gross_margin[5], opex_ratio[5], da_pct, capex_pct, nwc_pct},
              terminal:{g, exit_multiple},
              comps:{pe, ev_ebitda, ev_ebit},
              sotp:{segments:[{name, ebit, base_mult, bear_mult, bull_mult}]},
              weights:{dcf_gordon, dcf_exit, comps_pe, comps_ev, sotp}}
```

## 六、API 设计

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/analyze` | `{ticker, market}` → 抓取+标准化+自动假设+五模型全量结果+质量报告 |
| POST | `/api/recalculate` | `{financials, assumptions}` → 仅重算引擎（毫秒级，不触网） |
| GET | `/api/comps/pool` | 可比池数据（支持用户增删后重取） |
| PUT | `/api/project/save` | 保存当前项目（标的+假设+分部）至 SQLite |
| GET | `/api/project/list` | 历史项目清单 |

## 七、前端设计（互动式工作台）

**布局**：左侧固定导航（6 页签）+ 右侧主工作区。借鉴主流金融终端（Bloomberg 风格）与同类估值应用（Finchat/估值就三步）的卡片式分区。

| 页面 | 内容 | 关键交互 |
|---|---|---|
| ① 数据总览 | 标准化财报三年趋势卡 + 数据质量检查清单 | 缺失科目行内补录 |
| ② 假设参数 | WACC/预测/终值/权重 全部参数表单 | 任一修改 → 全站即时重算 |
| ③ DCF | 预测表、折现瀑布、双终值对比 | WACC×g 敏感性热力图 |
| ④ 可比公司 | 可比池表格（可增删行）+ 乘数分布箱线图 + 估值桥瀑布 | 分位数区间可视化 |
| ⑤ SOTP | 动态分部编辑器（增删分部行：名称+EBIT+三情境倍数） | 0分部自动隐藏该页签 |
| ⑥ 汇总看板 | **足球场图**(五大模型区间柱) + 加权中枢大数字卡 + 评级徽章 + 链路拓扑图 | 拖动权重滑杆实时重算 |

**技术要点**：ECharts 实现（足球场图=自定义 bar series；热力图=heatmap；箱线图=boxplot）。所有表格容器 `overflow:auto` + 可拖拽调高（可滚动优先原则）；深色导航白字、白底黑字，严禁白底白字（高对比度要求）；三情境切换按钮组全局共享。

## 十、验收标准（Definition of Done）

1. **还原验收**：`POST /api/recalculate` 传入范例表泡泡玛特数据 → DCF-Gordon ¥273.42、DCF-Exit ¥370.75、Comps-P/E ¥232.04、SOTP ¥327.54、综合中枢 ¥278.65，误差 ≤0.1%
2. **万能验收**：任选 1 只港股（如 00700.HK）+ 1 只美股（如 AAPL），输入代码 30 秒内完成抓取→估值→看板全流程
3. **降级验收**：构造亏损公司 → P/E 模型自动剔除且权重重分配；SOTP 零分部 → 页签自动隐藏
4. **交互验收**：修改任意假设（如 WACC 9.8%→11%）→ 全站数字与图表 <200ms 重算
5. **双市场验收**：港/美股各自科目录入样例通过映射正确性单测（含 IFRS-16 租赁负债口径差异）
6. **可读性验收**：全部界面白底黑字/深底白字高对比，长表格容器可滚动可调高

## 十一、风险与对策

| 风险 | 对策 |
|---|---|
| akshare 美股接口不稳定 | Provider 抽象层多源自动切换（yfinance 为主兜底） |
| 财报科目缺失/口径不一致 | 质量检查器黄色警告 + 手动补录兜底（已确认决策） |
| 自动生成的假设不合理 | 假设面板全暴露 + 行业默认值 + 历史回归双参考，用户终审 |
| 汇率/币种混杂（港股公司报人民币/港元） | 财报币种自动识别，统一换算至财报主币种展示 |
| 数据仅供研究产生误用 | 界面固定免责声明：输出为模型推演，非投资建议 |
